**Thesis Engine** 可以理解为：

> 一个帮你持续管理“投资观点”的系统，而不是一个直接告诉你买什么的系统。

它的核心不是预测，而是管理认知。

---

## 1. Thesis 是什么？

不是一句口号：

> AI 很牛，美股会涨。

而是一个可验证的投资假设：

> 未来 3-5 年，AI 基础设施资本开支仍将保持高位，因此纳指、半导体、数据中心、电力设备相关指数会持续获得估值支撑。

这才叫 Thesis。

因为它包含：

```text
主题：AI 基础设施
时间：3-5 年
传导链：AI 需求 → CapEx → 半导体/数据中心/电力
资产影响：纳指、半导体 ETF、电力设备 ETF
验证指标：云厂商 CapEx、Nvidia 收入、TSMC CoWoS、数据中心电力需求
```

---

## 2. Thesis Engine 解决什么问题？

它解决的是：

> 我曾经为什么看好？现在这个理由还成立吗？

投资中最大的问题不是没有信息，而是：

```text
新闻很多
观点很多
市场很吵
自己忘了最初判断
```

Thesis Engine 的作用是把这些东西结构化。

---

## 3. 最小模型

一个 Thesis 至少包含 7 个字段：

```ts
type Thesis = {
  title: string
  summary: string
  timeHorizon: "3m" | "6m" | "1y" | "3y" | "5y"
  affectedAssets: string[]
  causalChain: string[]
  keyAssumptions: string[]
  evidenceFor: Evidence[]
  evidenceAgainst: Evidence[]
  confidence: number
}
```

例如：

```text
Thesis:
AI 基础设施超级周期仍未结束

Causal Chain:
AI 应用需求增长
↓
云厂商继续扩大 CapEx
↓
GPU / HBM / 数据中心需求维持高位
↓
半导体和纳指获得支撑
```

---

## 4. 核心不是新闻，而是证据

普通新闻流是：

```text
今天发生了什么？
```

Thesis Engine 问的是：

```text
这条新闻支持还是削弱我的 Thesis？
```

例如：

### 新闻

微软上调 AI 数据中心资本开支。

系统判断：

```text
关联 Thesis：
AI 基础设施超级周期

影响方向：
支持

影响强度：
强

理由：
云厂商 CapEx 上调直接验证算力需求仍在扩张。
```

---

### 反向新闻

Meta 宣布削减 AI 基建预算。

系统判断：

```text
关联 Thesis：
AI 基础设施超级周期

影响方向：
削弱

影响强度：
中强

理由：
核心买方之一降低资本开支，说明需求可能阶段性放缓。
```

---

## 5. 这就是贝叶斯更新

每个 Thesis 都有一个初始信心：

```text
confidence = 65
```

新证据进来后：

```text
强支持 +8
弱支持 +2
中性 0
弱反对 -2
强反对 -8
```

最后变成：

```text
confidence = 73
```

重点不是这个分数多精准，而是：

> 每次变化都有证据链。

你以后回看时知道：

```text
为什么从 65 变成 73？
因为微软 CapEx 上调、Nvidia 指引超预期、TSMC 扩产。
```

## 7. 系统模块拆解

我建议拆成 6 个模块。

### A. Thesis Registry

观点库。

保存所有投资假设：

```text
AI 基础设施超级周期
中国资产估值修复
黄金长期配置
日本再通胀
美元流动性转向
```

每个观点都有：

```text
状态：active / watching / invalidated / archived
信心：0-100
时间周期
关联资产
```

---

### B. Evidence Inbox

证据收件箱。

所有新闻、财报、宏观数据、研报摘要先进入这里。

来源包括：

```text
RSS
公司公告
ETF 持仓
财报电话会
FRED
TradingView
X
手动笔记
```

第一版不需要自动化，甚至可以你手动粘贴新闻。

---

### C. Evidence Classifier

证据分类器。

AI 判断：

```text
这条信息关联哪个 Thesis？
是支持、反对，还是无关？
影响强度多大？
它影响的是哪条因果链？
```

输出结构：

```json
{
  "thesis": "AI Infrastructure Supercycle",
  "direction": "support",
  "strength": 4,
  "affected_assumption": "Cloud CapEx remains high",
  "reason": "Microsoft raised AI data center spending guidance."
}
```

---

### D. Confidence Updater

信心更新器。

不是简单加减分，而是要记录：

```text
之前信心
新证据
调整理由
之后信心
```

例如：

```text
65 → 72
原因：三家云厂商同时上调 CapEx，核心假设被强化。
```

---

### E. Asset Impact Mapper

资产影响映射器。

把 Thesis 连接到指数和基金：

```text
AI Infrastructure Supercycle
↓
QQQ / SOXX / SMH / 纳指100 / 半导体ETF
```

然后给每个资产一个暴露度：

```text
QQQ：中高
SMH：高
标普500：中
沪深300：低
```

这一步非常关键。

因为 Sora 是宽基指数基金平台，不是纯观点平台。

---

### F. Review Dashboard

回顾面板。

回答三个问题：

```text
现在我最相信哪些 Thesis？
哪些 Thesis 正在被削弱？
哪些资产暴露过高？
```

这才是用户每天打开平台真正想看的。

## 8. MVP 怎么做？

第一版不要做复杂系统。

你可以只做一个本地 JSON + CLI。

### 数据结构

```json
{
  "id": "ai-infra-supercycle",
  "title": "AI 基础设施超级周期仍未结束",
  "confidence": 68,
  "status": "active",
  "assets": ["NASDAQ100", "S&P500", "SOXX", "SMH"],
  "assumptions": [
    "云厂商 CapEx 维持高增长",
    "GPU/HBM 供给仍然紧张",
    "AI 应用需求继续扩张"
  ],
  "evidence": [
    {
      "date": "2026-06-09",
      "title": "某云厂商上调 AI 数据中心预算",
      "direction": "support",
      "strength": 4,
      "summary": "支持 CapEx 持续增长假设"
    }
  ]
}
```

### CLI 命令

```bash
sora thesis list
sora thesis add
sora evidence add
sora thesis review ai-infra-supercycle
sora thesis update-confidence
```

够了。

第一版要验证的是：

> 这种观点管理方式，对你自己是否真的有帮助。

---

## 9. 和 Serenity 的关系

Serenity 是：

```text
事件 → 公司 → 财务 → 估值 → Alpha
```

你的 Thesis Engine 是：

```text
事件 → Thesis → 指数/基金 → 配置判断
```

所以不是照搬，而是上移一层。

Serenity 更像猎人。

Thesis Engine 更像投资研究日志 + 认知系统。

---

## 10. 最重要的产品判断

这个功能可能是 Sora 的灵魂。

因为宽基指数平台如果只做：

```text
估值百分位
PE/PB
涨跌幅
基金列表
```

那很容易变成普通理财工具。

但如果加入 Thesis Engine，它就变成：

> 一个帮助长期投资者持续理解市场、跟踪投资逻辑、避免被短期噪音带偏的 Agentic Finance 产品。

这才像 AI Native 产品。

不是给用户更多数据。

而是帮用户维护一套不断更新的市场认知。
