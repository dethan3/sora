# Sora V2 模块化开发计划

## 顺序与提交策略

Desktop Web → 完整响应式 → PWA。每阶段独立审阅、检查和验收，不一次完成整个平台。
M0 分支 `feat/sora-v2-foundation`，从 main 创建，保留原 Python 内核，禁止强推覆盖。

| 阶段           | 模块                                                            | 验收门槛                                                               |
| -------------- | --------------------------------------------------------------- | ---------------------------------------------------------------------- |
| M0 foundation  | Workspace、Shell、五个路由、静态数据契约、基础 UI、CI、预览配置 | `pnpm check`、Wrangler dry-run；直接访问路由、搜索和异常恢复可用       |
| M1 Desktop Web | 基金详情 / 趋势说明、发现模块、本地关注与组合                   | 主桌面流程可闭环，刷新保留本地内容，输入校验、空态、导入导出有回归测试 |
| M2 Responsive  | 桌面细化、平板 / 手机布局、键盘与读屏检查                       | 1440、1024、768、390px 宽度人工验收；导航 / 表格 / 表单无不可达操作    |
| M3 PWA         | manifest、图标、安装、离线壳、更新策略                          | 安装及离线打开，更新可恢复，陈旧数据标记明确，无永久旧缓存             |
| 按需扩展       | 数据发布流水线、外部 Agent adapter、D1 / 账户                   | 分别形成需求与 ADR，具有独立权限、失败和恢复方案，不阻塞静态 Web       |

## M0 工作包

1. 审计 main 与 Python，检查目标分支是否存在并建立独立分支。
2. 创建工具链与五个路由，补基础组件与 JSON 校验。
3. 加入路由 / 导航 / 搜索 / 异常 / 计算测试和 CI。
4. 验证生产构建和 Cloudflare 静态配置，记录运行命令、范围、线上部署前提。
5. 检查 Python 文件无差异、main 指针未改，提交并普通推送 feature 分支。

## M1 Desktop Web

M0 完成视觉评审后，用户已授权继续 M1。
第一轮设计调整采用顶部四入口、冷灰与深墨蓝基底、蓝紫品牌色；首页加入组合界面预览，功能页使用直接标题与各自的信息布局。
M1 从 `0bcc320` 创建独立分支 `feat/sora-v2-m1`，沿用已确认风格和虚构样本。

- [x] feature 页面拆分，单一静态数据入口。
- [x] 基金详情、样本曲线、区间说明、单位、来源与日期。
- [x] JSON 地区 / 主题模块与 URL 筛选。
- [x] 本地关注增删、刷新保留与空态。
- [x] 持仓增改删、零成本、金额精度、多币种和缺失净值处理。
- [x] 版本化存储、备份往返、损坏恢复、清空确认。
- [x] 桌面流程及异常回归验证。

M2：集中验收 1440、1024、768、390px，细化移动表格、表单、详情图表与键盘 / 读屏流程。
M3：响应式稳定后增加 PWA；真实数据、D1、账户和 Agent 分别另立需求。
