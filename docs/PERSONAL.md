# 5.5 本地账号数据同步

本轮只实现和验证本地 Worker / D1。页面中的「保存到账号」表示请求当前连接的 Worker；本地开发使用本机 D1，尚未发布到公网。正式部署后沿用同一协议。

## 保存范围

| 数据                                 | 未登录                | 登录后             |
| ------------------------------------ | --------------------- | ------------------ |
| 基金关注与持仓（份额、总成本、币种） | 此浏览器 localStorage | 当前账号的 D1 数据 |
| 方向关注、研究线索关注与复盘         | 此浏览器              | 仍在此浏览器       |
| 公共目录、持仓披露和市场日线         | 公共资料              | 公共资料           |

登录不会自动上传原本地记录。账号数据读取失败会显示错误，保存按钮停用，支持重新读取；不会把失败的账号写入悄悄改成本地保存。保存结果未确认时仍保留输入与上一份已确认数据，同一操作重试沿用原操作编号。退出或切换账号会取消旧请求并重建个人页面，清除上一账号在组件中的状态；原游客记录保持不变。账号私有数据不写入浏览器持久缓存，API 响应为 `no-store`，PWA 继续只缓存公共内容。

## 本地使用

```sh
pnpm db:setup:local
pnpm dev:worker
```

已有 `.dev.vars` 和管理员账号可继续使用；新环境按 [Phase 5 说明](./PHASE5.md) 设置仅限本机的 Turnstile 测试 keys 并运行管理员 bootstrap。访问 `http://localhost:8787`，使用原有六只基金即可测试个人功能，无需先运行 AKTools 或配置 GitHub / Cloudflare 远程凭据。

- **游客**：关注基金、录入持仓，数据留在此浏览器。
- **登录后**：页面显示账号保存状态，关注和持仓从账号读取。可以在「我的账号」以及关注 / 组合页的「备份与数据管理」导入或导出。
- **原本地记录**：有数据时显示「查看并导入本地数据」。先核对公共目录；未收录、已下架或币种不匹配的项目明确列出，不上传，原件继续保留。关注合并去重；同一基金的持仓有差异时，必须选择保留账号已有版本或使用本次导入版本，不自动相加。
- **其他设备 / 浏览器**：登录同一账号后读取相同 D1 数据；窗口重新获得焦点时刷新，也可手动「重新读取账号数据」。本机联调可使用两个浏览器配置文件或独立会话验证。
- **并发修改**：旧版本写入返回冲突。先重新读取，再检查并提交；不会覆盖其他设备刚保存的结果。已打开的持仓编辑草稿不会自动覆盖新版本。
- **清空数据**：未登录只清空此浏览器的基金关注和持仓；登录后只清空当前账号的对应数据，并同步到其其他设备。方向和研究状态不受影响。

下架基金的已有账号记录继续可见、可导出和移除；不能新建或修改其持仓。尚未收录的游客记录可保留在原件中，待管理员收录后重新导入。

## 数据与事务

共享契约位于 `packages/market-data/src/personal.ts`，前端和 Worker 使用同一校验规则。每类最多 200 条，持仓按基金代码唯一。份额用十进制字符串（最多 4 位小数、最多 1,000,000 份），去除首尾空白后保留数字与小数位；总成本为最小货币单位整数 `costMinor`（CNY / USD / HKD 为分，KRW 为元），上限 1,000,000,000,000。不将总成本除以份额换成单价，不使用浮点数迁移金额。

迁移 `0005_personal.sql` 新建实际使用的 `positions(user_id,instrument_id,units,cost_minor,currency,...)`、`personal_accounts` 和 `personal_operations`。旧预留 `positions` 表是每份单价语义，保留为 `positions_legacy`；若曾手工写入，应先导出并核对，再用正确的总成本导入。迁移不会猜测换算旧值。原浏览器 `sora.personal.v1` 格式与备份文件仍可使用。

所有写入携带预期 `revision` 和 UUID `operationId`。Worker 从 Cookie 会话确定用户；请求中的 `ownerId` 只用于拒绝账号切换后的旧请求，不能用它选择其他人的数据。事务内重新确认会话、版本和基金状态，再更新关注、持仓、版本及幂等记录；任一步失败全部回滚。同一操作编号、相同请求重试只生效一次，并返回该账号当前快照；同一编号换内容返回冲突。不同操作同时修改相同版本，最多一个成功。

私有读取在同一条 SQL 中构造版本和数据快照，避免读出不同版本的关注、持仓。未改变的已下架记录允许保留，新增和修改必须是 ready 的公共基金且币种匹配。账户切换、旧请求结果、StrictMode 重挂载以及读取 / 保存竞态均有测试。

## 接口

| 接口                             | 用途                                  |
| -------------------------------- | ------------------------------------- |
| `GET /api/me/personal`           | `{ownerId, revision, state}` 一致快照 |
| `POST /api/me/personal`          | 按预期版本保存完整关注 / 持仓状态     |
| `GET/POST /api/me/watchlist`     | 查询 / 添加关注                       |
| `DELETE /api/me/watchlist/:code` | 移除关注                              |
| `GET/POST /api/me/positions`     | 查询 / 新建或更新单基金持仓           |
| `DELETE /api/me/positions/:code` | 移除持仓                              |
| `POST /api/me/import/preview`    | 核对可导入记录、不可用原因及冲突      |
| `POST /api/me/import`            | 按选择原子合并导入                    |

写操作校验 Origin、JSON、当前有效会话、请求大小及频率。完整保存格式：

```json
{
  "ownerId": "当前登录用户 ID",
  "revision": 0,
  "operationId": "客户端生成的 UUID",
  "state": {
    "schemaVersion": 1,
    "watchlist": ["SOXX"],
    "positions": [
      {
        "code": "SOXX",
        "units": "10.0000",
        "costMinor": 123456,
        "currency": "USD"
      }
    ]
  }
}
```

导入提交使用 `{ownerId,revision,operationId,localState,choices}`，`choices` 为冲突基金代码到 `local` / `cloud` 的映射。未知额外字段被拒绝；份额、成本、币种、条数和版本在服务端再次校验。

## 验证

`pnpm check` 验证共享数据契约、账号隔离、并发 / 重试、精确往返、导入冲突、保存失败保留草稿及原有页面回归。`pnpm check:worker` 使用全新临时 D1、真实 workerd、两个实际登录会话验证读取一致、其他账号隔离、版本冲突、导入与幂等回写；仅替换外部 Siteverify。正式浏览器联调使用独立临时 D1 和官方 Turnstile 测试 keys。

这里验证的是账号保存与迁移链路；持仓估值仍使用既有净值契约，不把 ETF 交易价格混成基金净值。真实公网跨设备访问、正式凭据与部署验收留到 5.6。
